# Project Defense AI — Demo Script

Estimated time: 5–7 minutes. Walk through all 18 steps below.

---

## Setup (before the demo)

1. Open two terminals.
2. **Terminal 1 — Backend:**
   ```
   cd ai-studnet-portal
   set PROJECT_DEFENSE_DEMO_MODE=true
   uvicorn app.main:app --reload --port 8000
   ```
   Wait for: `Application startup complete.`

3. **Terminal 2 — Frontend:**
   ```
   cd ai-studnet-portal/frontend
   npm run dev
   ```
   Wait for: `ready - started server on 0.0.0.0:3000`

4. Open `http://localhost:3000` in Chrome.

---

## The 18-Step Demo

### Step 1 — Landing redirect
The root page reads localStorage. Since no token is stored yet, it automatically redirects to `/login`.

### Step 2 — Login page
Show the clean login form. Point out the **Demo Quick-Login** buttons at the bottom (only visible when `NEXT_PUBLIC_DEMO_MODE=true`).

### Step 3 — Student login
Click **Student Demo**. The app posts to `/auth/token`, stores the JWT, fetches `/auth/me`, and redirects to `/student`.

### Step 4 — Student dashboard
Show the three stat cards: **Total Tasks / Submitted / Pending**. Point out the task list with colored status chips.

Scroll to show:
- A task with "COMPLETED" status (Aarav's task — pre-seeded evaluation)
- A task with "PENDING" status (no submission yet)

### Step 5 — View task details
Click a task card. The `/student/task/[id]` page shows:
- Full problem statement
- Acceptance criteria list
- Expected concepts
- **Submit Work** button

### Step 6 — Submit form
Click **Submit Work**. Show the three-field form:
- GitHub Commit URL
- Approach description
- Self-assessment dropdown

Fill in a demo commit URL, e.g.: `https://github.com/demo/repo/commit/abc123def`

Click **Submit for AI Evaluation**.

### Step 7 — Evaluation animation
Watch the five-step progress animation:
1. Reading task requirements ✓
2. Fetching commit ✓
3. Analysing changed files ✓
4. Checking acceptance criteria ✓
5. Evaluating implementation ✓

"The AI pipeline runs — context builder, evaluator, validator — in real time."

### Step 8 — Evaluation result
Show the result view:
- Score badge (0–10, color-coded)
- Confidence percentage
- Dimension scores (code quality, test coverage, architecture…) with progress bars
- Acceptance criteria pass/fail list
- Issues found (EvidenceCard with file + line)
- Strengths
- Missing requirements

"All of this is generated by the AI engine in one pipeline call."

### Step 9 — Logout and mentor login
Click **Logout**. On the login page, click **Mentor Demo**.

### Step 10 — Mentor dashboard
Show the four stat cards: **Total Students / Submitted Today / Needs Review / Average Score**.

Point out the **Requires Attention** section — cards for students whose evaluations were flagged for human review (amber border, AI attention reason shown).

### Step 11 — Student table
Scroll to the **All Students** table. Each row shows:
- Student name and email
- Current task
- AI score badge
- AI status chip (completed / needs_human_review)
- Mentor review status

"Five students, all pre-seeded. Aarav has a completed evaluation, Priya and Sneha are flagged for review."

### Step 12 — Open a needs-review evaluation
Click **Review** on a flagged student (e.g., Priya Nair). The `/mentor/evaluations/[id]` page loads.

### Step 13 — Evaluation detail
Walk through the detail sections:
- Score + confidence header
- Acceptance criteria (PASS/FAIL/PARTIAL per criterion)
- Dimension bars with AI reasoning
- Issues + evidence (file paths, line numbers, severity)
- Security concerns (if any)
- Strengths and missing requirements

"Everything the mentor needs — no digging through repos."

### Step 14 — Mentor review form
Scroll to the **Mentor Review** section. Show the four decision buttons:
- **Approve** (green)
- **Request Changes** (amber)
- **Reject** (red)
- **Override Score** (indigo — reveals a score input)

### Step 15 — Submit a review
Select **Request Changes**, type feedback like: "Good attempt — missing error handling in the database layer. Please add try/catch around all DB calls."

Click **Submit Review**.

### Step 16 — Confirmation
Show the green **Mentor Review Completed** banner. The decision chip updates inline. "Update review" link allows re-submission.

### Step 17 — Evaluations list
Click **Evaluations** in the nav. Show the full table with the filter toggle: "Needs review only" — toggles to show only flagged evaluations.

Click through to a completed evaluation to show the same detail view (read-only if already reviewed).

### Step 18 — Full loop
Summarize the workflow the demo just demonstrated:
> Student logs in → views task → submits commit URL → AI evaluates in real time → score + evidence → mentor reviews → decision recorded

"The entire Milestone 1–5 backend — auth, event bus, GitHub integration, AI engine — is running live underneath this UI."

---

## Fallback if backend is slow

If the evaluation call hangs, refresh and use the pre-seeded evaluations. Navigate to `/mentor/evaluations` directly and click any existing evaluation to show the detail view.
